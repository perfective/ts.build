= Perfective Build for TypeScript

The `@perfective/build` package provides base configurations
and presets for tools like Gulp, TypeScript, Babel, etc.
to reduce code duplication between project setups.


== Installation

[source,bash]
----
npm install --save-dev \
    @perfective/build \
    typescript
----


== Building a TypeScript project

The main purpose of `@perfective/build` is to compile a TypeScript library into **one** `dist/` directory
with ES modules (`.js`), CommonJS (`.cjs`), and declaration files (`.d.ts`),
instead of using two separate TypeScript compiler output trees.

. Check that dev dependencies include correct versions of `@babel/core`, `gulp`, and `typescript`.
`@babel/core` and `gulp` are optional peer dependencies of `@perfective/build`;
install them when using the Gulp TypeScript tasks and `@perfective/build/babel`.
The TypeScript Gulp tasks run compiled output through `gulp-babel`, which requires `@babel/core`.
+
[source,json]
----
{
    "devDependencies": {
        "@babel/core": "^8.1.0",
        "gulp": "^5.0.1",
        "typescript": "~6.0.3"
    }
}
----
+
. Setup `tsconfig.json` using the base `tsconfig.strict.json` configuration.
+
[source,json]
----
{
    "extends": "@perfective/build/tsconfig.strict.json",
    "compilerOptions": {
        "rootDir": "./src"
    },
    "exclude": [
        "dist"
    ]
}
----
+
Add a `tsconfig.build.json` used by the Gulp TypeScript tasks (defaults to `./tsconfig.build.json`).
See <<typescript-configuration>> for what the base configuration sets and what to override.
+
. Add the `RequireExtension` and `ImportExtension` plugins to your `babel.config.js`.
`RequireExtension` appends the `.cjs` extension to relative paths in `require()` statements.
`ImportExtension` adds the required `.mjs` (or `.js`) extension to relative `import` and `export` paths for ES modules.
The TypeScript Gulp tasks run output through `gulp-babel`, which applies this config.
+
[source,javascript]
----
import { babelPluginImportExtension, babelPluginRequireExtension } from '@perfective/build/babel';

export default {
    presets: [],
    plugins: [
        babelPluginRequireExtension,
        babelPluginImportExtension('js'), // <.>
    ]
};
----
<.> Override the default extension (`mjs`).
+
. Create a `gulpfile.js` that emits ESM, CommonJS, and declarations into the same `dist/` tree:
+
[source,javascript]
----
import gulp from 'gulp';

import * as build from '@perfective/build/gulp';

export const clean = build.clean(['./dist']);
export const docs = build.asciidoctor();

export default gulp.series(
    clean,
    build.typescript.esmBuild(),
    build.typescript.cjsBuild(),
    build.typescript.tsDeclarations(),
    build.packageJson.subPackageJson('@scope/package', {
        type: 'module',
    }),
    build.packageJson.packageJson(),
    build.copy([
        './LICENSE*',
        './CHANGELOG*',
        './README*',
    ], './dist'),
    docs,
);
----
+
For an **ESM-only** package (for example, ESLint flat configs), omit `cjsBuild()`
and clear the CommonJS entry when generating `package.json`:
+
[source,javascript]
----
build.typescript.esmBuild(),
build.typescript.tsDeclarations(),
build.packageJson.packageJson({
    main: undefined,
    module: './index.js',
    types: './index.d.ts',
}),
----


[#typescript-configuration]
== TypeScript configuration

`@perfective/build/tsconfig.strict.json` is a base configuration to `extends` from.
It lists every relevant `compilerOptions` value explicitly (including defaults),
so a TypeScript upgrade that changes a default does not silently change the build.
It sets no `include`, `exclude`, `files`, `rootDir`, `outDir`, `lib`, or `types`:
those depend on the project layout and runtime.

=== Project files

A typical project has two configuration files:

`tsconfig.json`::
Extends `@perfective/build/tsconfig.strict.json`.
Used by the IDE, ESLint, and Jest (`ts-jest`), so it includes tests.
+
[source,json]
----
{
    "extends": "@perfective/build/tsconfig.strict.json",
    "compilerOptions": {
        "rootDir": "./src"
    },
    "exclude": ["dist"]
}
----

`tsconfig.build.json`::
Extends `./tsconfig.json` and is used by the Gulp TypeScript tasks.
Excludes tests and test helpers, and turns off output the published package does not need.
+
[source,json]
----
{
    "extends": "./tsconfig.json",
    "compilerOptions": {
        "outDir": "dist",
        "rootDir": "src",
        "declaration": false, // <.>
        "declarationMap": false,
        "sourceMap": false
    },
    "exclude": ["dist", "src/**/*.spec.ts"]
}
----
<.> `esmBuild()` and `cjsBuild()` do not need declarations;
`tsDeclarations()` forces `declaration: true` for its own emit.

=== Options overridden by the Gulp tasks

The Gulp TypeScript tasks pass extra `compilerOptions` on top of the project configuration,
so the `module` value in `tsconfig.strict.json` does not define the published module format.

[cols="1,3"]
|===
|Task |Overrides

|`esmBuild()`
|`module: esnext`, `allowSyntheticDefaultImports: true`

|`cjsBuild()`
|`module: commonjs`, `esModuleInterop: true`

|`tsDeclarations()`
|`module: esnext`, `declaration: true`, `emitDeclarationOnly: true`, `removeComments: false`

|`tsBuild()`
|None (uses the project configuration as is)
|===

=== Strictness

`strict` is enabled, and each option it implies is also listed explicitly:
`alwaysStrict`, `noImplicitAny`, `noImplicitThis`, `strictBindCallApply`, `strictBuiltinIteratorReturn`,
`strictFunctionTypes`, `strictNullChecks`, `strictPropertyInitialization`, `useUnknownInCatchVariables`.

Additional checks beyond `strict`:

* `exactOptionalPropertyTypes` — an optional property does not accept an explicit `undefined`
unless its type includes `undefined`.
* `noFallthroughCasesInSwitch`, `noImplicitOverride`, `noImplicitReturns`.
* `noPropertyAccessFromIndexSignature` — index signature properties require bracket access.
* `noUncheckedSideEffectImports` — side-effect imports (`import './x'`) must resolve.
* `noUnusedLocals`, `noUnusedParameters`.
* `allowUnreachableCode: false`, `allowUnusedLabels: false` — report errors instead of warnings.
* `forceConsistentCasingInFileNames`.

`noUncheckedIndexedAccess` is disabled.

=== Modules and interoperability

* `module: commonjs` and `moduleResolution: bundler`.
The Gulp tasks override `module` (see above);
`bundler` resolution allows extensionless relative imports,
and the Babel plugins add the extensions in the emitted files.
* `esModuleInterop` and `allowSyntheticDefaultImports` are enabled.
* `isolatedModules`, `resolveJsonModule`, `allowJs`, `checkJs`, `allowArbitraryExtensions`,
`allowImportingTsExtensions`, and `allowUmdGlobalAccess` are disabled.
* `importsNotUsedAsValues: remove` is deprecated and matches the default behavior
(imports used only as types are dropped from the output).

=== Language and emit

* `target: es2015` (override it to use newer syntax and libraries, e.g. `es2017`).
* `experimentalDecorators` is enabled and `emitDecoratorMetadata` is disabled.
* `useDefineForClassFields: false` keeps class fields as constructor assignments.
* `declaration`, `declarationMap`, and `sourceMap` are enabled.
* `removeComments` is enabled (`tsDeclarations()` keeps comments in `.d.ts` files).
* `noEmitOnError` is enabled; `importHelpers` and `noEmitHelpers` are disabled (helpers are inlined).
* `preserveConstEnums` is enabled; `stripInternal` is disabled.
* `newLine: lf`, `emitBOM: false`.

=== Project and diagnostics

* `incremental` is enabled (add `*.tsbuildinfo` to `clean` and `.gitignore`).
* `skipLibCheck` is disabled, so dependency declaration files are type-checked.
* `noErrorTruncation` and `pretty` are enabled.

=== Common overrides

* `rootDir`, `outDir`, `include`/`exclude` — always project-specific.
* `target` and `lib` — for newer language features (e.g. `"target": "es2017"`).
* `types` — to limit global types (e.g. `["node"]` or `["jest"]`).


== Gulp tasks

Import task factories from `@perfective/build/gulp`.
Each factory returns a Gulp task function.

=== `clean(patterns, options?)`

Deletes files with https://www.npmjs.com/package/del[`del`].
`patterns` is a glob or an array of globs; `options` is passed through to `deleteAsync`.

[source,javascript]
----
export const clean = build.clean(['./dist', '*.tsbuildinfo']);
----

=== `copy(source, destination)`

Copies files with `gulp.src(source).pipe(gulp.dest(destination))`.

[source,javascript]
----
build.copy(['./LICENSE*', './CHANGELOG*', './README*'], './dist')
----

=== `asciidoctor(options?)`

Renders AsciiDoc into HTML for the published package.

Defaults::
* `source`: `./src/index.adoc`
* `output`: `./dist`
* `name`: `docs` (output basename, e.g. `docs.html`)

=== `file.createFile(filepath, contents)` / `file.createJsonFile(filepath, json)`

Writes a Vinyl file into the project (for example, nested `package.json` files under `dist/`).

[source,javascript]
----
build.file.createJsonFile('./dist/jest/package.json', {
    name: '@scope/package/jest',
    type: 'module',
    module: '../config/jest/index.js',
    types: '../config/jest/index.d.ts',
    exports: {
        '.': {
            types: '../config/jest/index.d.ts',
            import: '../config/jest/index.js',
        },
    },
    sideEffects: false,
})
----

=== `typescript`

All TypeScript tasks accept `{ config, output }` (defaults: `./tsconfig.build.json`, `./dist`).
Each task overrides `compilerOptions.module` for that emit; do not rely on the base `tsconfig` `module` alone.

`esmBuild()`::
Compiles with `module: esnext`, runs Babel, writes `.js` files.

`cjsBuild()`::
Compiles with `module: commonjs`, runs Babel, renames `.js` to `.cjs`.

`tsDeclarations()`::
Emits `.d.ts` only (`emitDeclarationOnly`), keeps comments.

`tsBuild()`::
Plain TypeScript emit with the project config (no Babel, no rename).

=== `packageJson`

Generate publishable `package.json` files under `output` (default `./dist`).

`subPackageJson(packageName, options?)`::
For each `dist/*/index.js`, writes a scoped sub-package `package.json`
named `{packageName}/{directory}` (for Node subpath / directory imports).
Run this **before** `packageJson()` so root `exports` can discover those files.

`packageJson(options?, overrides?, exports?)`::
Copies the root `package.json` into `output`, drops `devDependencies`,
forces `scripts` to `{}`, and builds `exports` for `.` plus discovered sub-packages.
Default entry fields: `main: './index.cjs'`, `module: './index.js'`, `types: './index.d.ts'`.
* `options` — merged into the result (including `main` / `module` / `types` / `output`).
* `overrides` — applied last (deep merge via `gulp-json-editor`).
* `exports` — extra `exports` entries merged after auto-discovered subpaths.


== Setup Prettier

. Add `prettier` as a dev dependency:
+
[source,json]
----
{
    "devDependencies": {
        "prettier": "^3.9.10"
    }
}
----
+
. Setup `.prettierrc.js`:
+
[source,js]
----
import { config } from '@perfective/build/prettier';

export default config;
----
+
See <<prettier-configuration>> for what the shared configuration sets and how to override it.
+
. Setup `.prettierignore`:
+
[source,ignore]
----
# Build
dist

# ESLint
*.js
*.cjs
*.mjs
*.jsx
*.ts
*.cts
*.mts
*.tsx
----
+
. Update `package.json` scripts.
+
[source,json]
----
{
    "scripts": {
        "lint": "npm run lint:prettier",
        "lint:prettier": "prettier --write .",
        "lint:prettier:build": "prettier --check ."
    }
}
----
+
Use `lint:prettier` during development (to fix code automatically)
and `lint:prettier:build` to verify the build (to fail if code is not formatted).


[#prettier-configuration]
== Prettier configuration

`@perfective/build/prettier` exports a `config` object to use as the Prettier configuration.
It lists every formatting option explicitly (including defaults),
so a Prettier upgrade that changes a default does not silently reformat the project.

The suggested `.prettierignore` excludes JavaScript and TypeScript files:
they are expected to be formatted by ESLint (for example, with `@perfective/eslint-config`),
so Prettier formats the remaining files (JSON, YAML, Markdown, HTML, CSS, etc.).

=== Options

A value that spans the "Value" and "Default" columns matches the Prettier default.

[cols="2,1,1,3"]
|===
|Option |Value |Default |Effect

|`printWidth`
|`120`
|`80`
|Tries to keep lines within 120 characters
(long strings, URLs, and some syntax can still exceed it).

|`tabWidth`
|`4`
|`2`
|Indents with 4 spaces.

|`useTabs`
2+|`false`
|Indents with spaces.

|`endOfLine`
2+|`'lf'`
|Uses line feed (`\n`) line endings.

|`semi`
2+|`true`
|Adds semicolons at the end of statements.

|`singleQuote`
|`true`
|`false`
|Uses single quotes (except in JSX attributes, see `jsxSingleQuote`).

|`jsxSingleQuote`
2+|`false`
|Uses double quotes in JSX attributes.

|`quoteProps`
|`'consistent'`
|`'as-needed'`
|Quotes all properties of an object if at least one property requires quotes.

|`trailingComma`
2+|`'all'`
|Adds trailing commas wherever possible (including function parameters and arguments).

|`bracketSpacing`
2+|`true`
|Adds spaces between braces in object literals (`{ a: 1 }`).

|`objectWrap`
2+|`'preserve'`
|Keeps an object multi-line if there is a newline after its opening brace.

|`arrowParens`
|`'avoid'`
|`'always'`
|Omits parentheses around a single arrow function parameter (`x => x`).

|`experimentalTernaries`
2+|`false`
|Formats nested ternaries with the default (non-experimental) style.

|`experimentalOperatorPosition`
|`'start'`
|`'end'`
|Puts binary operators at the start of a wrapped line.

|`bracketSameLine`
|`true`
|`false`
|Puts the `>` of a multi-line element at the end of its last attribute line.
In HTML, Angular, and Vue, this applies to empty, whitespace-only, void, and self-closing elements
(e.g., `<img>`, `<input>`, `<my-cmp />`);
with `htmlWhitespaceSensitivity: 'strict'`, an element with other content (text or child elements)
keeps `>` on the following line.
In JSX, it applies to every element that is not self-closing (`/>` stays on its own line).

|`singleAttributePerLine`
|`true`
|`false`
|Puts each attribute on its own line when an HTML, Angular, JSX, or Vue element has more than one attribute
(even if the opening tag fits within `printWidth`).

|`htmlWhitespaceSensitivity`
|`'strict'`
|`'css'`
|Treats whitespace around all HTML elements as significant.

|`vueIndentScriptAndStyle`
|`true`
|`false`
|Indents the contents of `<script>` and `<style>` tags in Vue files.

|`proseWrap`
2+|`'preserve'`
|Keeps Markdown line breaks as written
(compatible with https://sembr.org/[semantic line breaks]).

|`embeddedLanguageFormatting`
2+|`'auto'`
|Formats embedded code (e.g., CSS in JS or code blocks in Markdown) when Prettier recognizes it.

|`insertPragma`
2+|`false`
|Does not insert a `@format` pragma into formatted files.

|`requirePragma`
2+|`false`
|Formats files without requiring a `@format` pragma.

|`checkIgnorePragma`
2+|`false`
|Formats files even if their first docblock contains a `@noprettier` or `@noformat` pragma.
|===

=== Overriding options

Spread the shared `config` and add options or
https://prettier.io/docs/configuration#configuration-overrides[`overrides`] for specific files:

[source,js]
----
import { config } from '@perfective/build/prettier';

export default {
    ...config,
    overrides: [
        {
            files: '*.md',
            options: {
                proseWrap: 'always',
            },
        },
    ],
};
----


== Setup Jest

. Add `jest` and related peer dependencies as dev dependencies:
+
[source,json]
----
{
    "devDependencies": {
        "@types/jest": "^30.0.0",
        "jest": "^30.5.2",
        "ts-jest": "^29.4.15"
    }
}
----
+
. Setup `jest.config.js`:
+
[source,js]
----
import { config } from '@perfective/build/jest';

export default config;
----
+
. Update `package.json` scripts:
+
[source,json]
----
{
    "scripts": {
        "test": "jest",
        "test:build": "jest --clearCache && jest --collectCoverage"
    }
}
----
+
Use `test` for development testing
and `test:build` to test during the build (and fail if test coverage is not sufficient).
+
See <<jest-configuration>> for what the shared configuration sets and how to override it.


[#jest-configuration]
== Jest configuration

`@perfective/build/jest` exports a `config` object to use as the Jest configuration.
It runs TypeScript tests from the `src` directory with `ts-jest`
and requires 100% test coverage when coverage is collected.

=== Options

A value that spans the "Value" and "Default" columns matches the Jest default.

[cols="2,2,2,3"]
|===
|Option |Value |Default |Effect

|`rootDir`
|`'./src'`
|The directory of the configuration file
|Searches for tests and collects coverage only in `src`
(relative to the configuration file).
Prevents the "jest-haste-map: Haste module naming collision" error
when `package.json` is copied into `dist`.

|`preset`
|`'ts-jest'`
|None
|Applies the `ts-jest` preset.

|`transform`
|`'^.+\\.tsx?$'` with `ts-jest`
|`'\\.[jt]sx?$'` with `babel-jest`
|Compiles `.ts` and `.tsx` files with `ts-jest` using `./tsconfig.json`
(resolved from the directory Jest runs in, not from `rootDir`).
JavaScript files are not transformed.

|`testEnvironment`
2+|`'node'`
|Runs tests in Node.js (without a DOM).

|`testPathIgnorePatterns`
|`['/node_modules/', '/dist/']`
|`['/node_modules/']`
|Ignores tests in `node_modules` and `dist`.

|`errorOnDeprecated`
|`true`
|`false`
|Throws an error when a test calls a deprecated Jest API.

|`collectCoverage`
2+|`false`
|Collects coverage only when requested (e.g., `jest --collectCoverage`).

|`coverageReporters`
|`['text']`
|`['clover', 'json', 'lcov', 'text']`
|Prints the coverage summary to the console and does not write coverage files.

|`coverageThreshold`
|100% `global` statements, branches, functions, and lines
|None
|Fails the run if coverage is below 100%.
Coverage is measured only for files loaded by tests (`collectCoverageFrom` is not set),
so a source file without tests does not lower it.

|`verbose`
2+|`false`
|Does not report each individual test result
(Jest still does when it runs a single test file).
|===

=== Overriding options

Spread the shared `config` and add or replace options:

[source,js]
----
import { config } from '@perfective/build/jest';

export default {
    ...config,
    testEnvironment: 'jsdom', // <.>
    collectCoverageFrom: ['**/*.ts', '!**/*.spec.ts'], // <.>
};
----
<.> Requires the `jest-environment-jsdom` package.
<.> Measures coverage for every TypeScript source file in `rootDir`, including files without tests.

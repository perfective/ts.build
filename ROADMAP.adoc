== Automated PR review

Cursor Review requests a Cursor review of each PR head with an `@cursoragent review` comment.
Cursor Bugbot, Cursor Automations, and the Cloud Agents API bill outside the included usage,
and Cursor ignores the comment from `github-actions[bot]`,
so the comment is posted with the maintainer's fine-grained token.

* Add a fix loop for the findings (Claude fixes in rounds 1 and 2) and resolve the fixed threads.


== Quality control

Required before any major changes.

* Lint the package's own JavaScript code and type-check it with TypeScript
without introducing circular dependencies (`@perfective/eslint-config` depends on `@perfective/build`).
* Add integration tests to verify that consumers (`ts.common`, `eslint-config`) still build
(Perfective packages target 100% coverage; this repo has no tests yet).
* If the Workflow Change check ever flags a change that nobody expected,
move the jobs that use secrets to triggers that run from `main`
(`workflow_run` for Dependency Review, and comment-only triggers for `claude.yaml`).
The job that `workflow_run` starts must not check out or run the PR head,
because it has the secret and runs from `main` with the base repository's token.


== Major changes

To be discussed in detail after the technical debt is caught up.

=== Remove Gulp and Babel

The goal is to depend only on TypeScript, Prettier, and Jest.

* Replace the Babel import extension plugins with TypeScript options
(e.g., `rewriteRelativeImportExtensions` or `.js` extensions in imports with `module: nodenext`).
Requires changing imports in `ts.common`.
* Replace the Gulp tasks.
* Migrate this package from hand-written ESM JavaScript to TypeScript without a painful self-rebuild cycle.

=== Package output

* Decide whether consumers still need CommonJS output.
Removing it removes the `cjsBuild` task and the `RequireExtension` plugin.
* Remove generated sub-package `package.json` files that exist for compatibility of sub-path imports.
* Check whether CommonJS consumers of `@perfective/build` itself rely on `require(esm)`
(the `require` exports point to ES modules).
* Drop the `docs.html` documentation and the `@asciidoctor/gulp-asciidoctor` dependency.
* Decide whether the unused root `src/index.js` barrel should remain for compatibility or be removed.
* Optionally slim the install surface: `gulp` is both a hard dependency and an optional peer.

=== TypeScript configuration

* Revisit `tsconfig/tsconfig.strict.json` default `"module": "commonjs"`
and `"moduleResolution": "bundler"` (set for TypeScript 6 after `node10` was deprecated;
Gulp already overrides `module` per emit target).
On TypeScript 6 this pair is valid.
`cjsBuild()` keeps `module: commonjs` so emit stays CommonJS for the Babel `.cjs` rewrite.
`node16` / `nodenext` are not a drop-in:
they reject extensionless imports and, when `package.json` has `"type": "module"`, emit ESM.
Prefer a modern baseline such as `NodeNext` once consumers are accounted for.
* TypeScript 6 defaults `types` to `[]`.
The strict config sets `"types": ["*"]` so installed `@types` packages stay in the program,
which is what an unset `types` did through TypeScript 5.9.
`@types/node` references the `es2020` lib,
so `Array.prototype.includes`, `Object.entries`, and string padding stay visible at `target: es2015`.
* Choose a newer `target` than `es2015`.
* Move `experimentalDecorators` out of the base configuration (required only for Angular).
* Review `useDefineForClassFields: false` (legacy from the ES2015 target).
* Remove the `importsNotUsedAsValues` option (deprecated since TypeScript 5.0).

=== Known limitations

* `babelPluginRequireExtension` only handles `require()` calls that initialize a variable
(`const`, `let`, or `var`, e.g., `var x = require('./y')`)
and fails the build on any other `require()` call with a string literal
(e.g., `__importDefault(require('./y'))`) and on `require()` without arguments,
so CommonJS output does not support default or namespace imports, `export * from`, `export * as ns from`,
side-effect imports, or dynamic `import()`.
`export * as ns from` emits an assignment (`exports.ns = require('./y')`)
and fails even without `esModuleInterop`.
* `babelPluginRequireExtension` does not resolve directories
(`const dir = require('./dir')` becomes `const dir = require('./dir.cjs')`).
* `babelPluginImportExtension` resolves directories relative to the compiled file path,
which `gulp-typescript` places in `outDir` when it is set (as in the documented `tsconfig.build.json`),
so on a clean build `'./dir'` becomes `'./dir.js'`.
